# Header writer and template engine

Story #37 added the header writer and the template engine of the generators. Each generator uses these parts. The templates of each target are not in this story (M5, M6, M7).

- Header writer: `src/dsml/generate/header.py`.
- Safe names: `src/dsml/generate/names.py`.
- Template engine: `src/dsml/generate/templates.py`.
- Package templates: `src/dsml/templates/` (package data).
- Tests: `tests/test_header.py`, `tests/test_names.py`, `tests/test_templates.py`.
- Golden file: `tests/golden/templates/service_gen.py`, from the test template `tests/templates/example/service_gen.py.j2`.

## Header

Each generated source file that permits comments starts with two comment lines (PRD-TRACE-005):

```text
# Generated by dsml 1. Do not edit.
# Elements: OrderService::CancelOrder, OrderService::Order, R-001
```

- The header gives only the major version of the toolchain (PRD-CORE-038).
- The identities are in the order of their code points, with no duplicates. A file with no elements gets the line `Elements:` with no identity.
- An identity that is empty, has a line break, or has a space at the start or at the end gives an error.

| File type | Comment start | Header |
| --- | --- | --- |
| Python | `#` | Yes |
| TypeScript | `//` | Yes |
| HCL | `#` | Yes |
| YAML | `#` | Yes |
| TOML | `#` | Yes |
| Dockerfile | `#` | Yes |
| JSON | None | No |

A template writes the header with this line at the start:

```jinja
{% include "common/header.j2" %}
```

The template data must contain `file_type` and `elements`. For JSON, the include writes nothing.

A Dockerfile parser directive, for example `# syntax=`, must be on the first line of a Dockerfile. Thus a Dockerfile template must not have a parser directive.

## Template engine

The engine is Jinja 3.1.6 (PyPI package `Jinja2`, BSD-3-Clause license). `src/dsml/versions.toml` records the version. The engine has these fixed settings:

| Setting | Value | Reason |
| --- | --- | --- |
| Undefined values | `StrictUndefined`. An undefined value or attribute gives an error. The value None also gives an error. | No empty text in the output because of a model defect. |
| Line ends | LF. The engine changes CR LF and CR in a template to LF. CR in the data gives an error. | PRD-CORE-034 |
| End of file | One LF. | PRD-CORE-034 |
| Encoding | UTF-8 with no byte order mark. | PRD-CORE-034 |
| Whitespace control | `trim_blocks` and `lstrip_blocks` are on. | The same template gives the same whitespace. |
| Escape | Off. | The output is source code, not HTML. |
| Sandbox | `ImmutableSandboxedEnvironment`. A template cannot read Python internals or change its data. | PRD-CORE-033 |
| Random values | The filter `random` and the global `lipsum` are removed. | PRD-CORE-033 |
| Clock and environment | No global gives the clock or the process environment. | PRD-CORE-033 |
| Files | The engine reads templates only from the template folder. A name with `..` or a symbolic link out of the folder gives an error. | PRD-CORE-033 |
| Extensions | None. | Fewer sources of change. |

## Filters

| Filter | Result |
| --- | --- |
| `sorted` | A list in the order of the code points. `sorted("name")` sorts by an attribute. `sorted(unique=true)` removes duplicates. |
| `snake_case` | `cancel_order` |
| `kebab_case` | `cancel-order` |
| `pascal_case` | `CancelOrder` |
| `camel_case` | `cancelOrder` |
| `python_name` | Snake case. A Python keyword gets `_` at the end, for example `class_`. |

The Jinja filter `sort` ignores case by default. Use the filter `sorted` for each list in the output (PRD-CORE-031).

## Format of the output

The templates must give their output in the format of the pinned formatter (PRD-CORE-035). The generator does not run a formatter. The CI step "Check the format of the golden files" runs `ruff format --check` on `tests/golden/`. The formatters of the other file types come with their generators.
